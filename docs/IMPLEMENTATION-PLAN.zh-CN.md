# CEM-S Studio 执行计划

> 本文件是近期开发的可执行清单。长期目标和完整能力边界见仓库根目录的 `ROADMAP.zh-CN.md`。

## 当前目标

让资源包作者在最新版 Blockbench（当前 smoke 验证版本：`5.1.6`）中完成以下闭环：

1. 新建项目时选择 Minecraft 版本、宿主实体和资源包。
2. 自动得到原版参考骨架，并明确区分“定位参考”和“导出模型”。
3. 把 Cube/Group 放进参考部件后自动绑定，必要时支持跨锚点移动和重置。
4. 为不同 Cube、Face 使用不同材质和 UV，且参考模型材质不进入用户图集。
5. 直接从当前项目配置导出资源包，不再重复选择绑定工具或手写 GLSL。
6. 在真实 Minecraft 客户端中验证资源包加载、坐标方向、旋转和 UV 结果。

## 近期批次

### A. Minecraft 实机验证准备

- [x] 生成独立的 `CEM-S Studio Verification` 测试资源包，不覆盖用户已有资源包。
- [x] 测试包包含一个简单的 Pig 模型、纹理 marker、模型 ID 和运行时版本说明。
- [x] 记录 `1.21.11` 资源包加载结果、shader 编译日志和模型坐标方向；UV 90/270 仍待单独实机验证。
- [ ] 在 `1.21.6` 与 `26.1+` 建立独立证据记录；未实机验证的版本不得标记为通过。

### B. 新建项目与主工作栏

- [ ] 新建 `.cemst` 时强制完成实体、版本和资源包选择。
- [ ] 首屏显示项目状态、参考模型、绑定状态、材质状态和下一步操作。
- [ ] 所有常用操作集中到 CEM-S Studio 工作栏：添加参考、创建模型、自动绑定、材质、导出、诊断。
- [ ] UI 不显示 `undefined`、GLSL、顶点编号或内部输出路径等实现细节。

### C. 自动绑定与挂件工作流

- [ ] Cube/Group 拖入参考部件即建立绑定，移出或改名时同步更新。
- [ ] 支持宿主模型与定位参考模型独立选择，例如“鞘翅宿主 + 玩家参考骨架”。
- [ ] 支持一个挂件拆分到多个锚点，并自动计算相对位置、旋转和缩放。
- [ ] 提供选中部件的绑定诊断、批量重新绑定和“重置到锚点”。

### D. 材质与参考模型隔离

- [ ] 每个 Cube、Face 可选择独立 Blockbench Texture 和 UV 区域。
- [ ] Create Texture 只收集用户模型实际引用的材质，排除参考模型材质。
- [ ] 多纹理图集导出时写入稳定的路径映射，并在缺少可表达的运行时能力时提前报错。
- [ ] 预览同时显示参考骨架和用户模型，但使用独立的辅助显示层。

### E. 原模型与渲染能力

- [ ] 提供保留、隐藏未匹配部件和替换指定部件的可视化选项。
- [ ] Group 渲染属性继续继承到子 Cube，显式 Cube 属性优先。
- [ ] 仅在 CEM-S runtime 已支持时开放叠加、背面剔除和渲染顺序；否则显示能力限制和修复建议。

## 验收与回归

每个批次完成后运行：

```powershell
npm test
npm run check
npm run test:blockbench
git diff --check
```

发布前还必须满足：

- 至少一个玩家/盔甲挂件、一个普通生物挂件和一个多部件模型完成客户端验证。
- `.cemst` v1/v2/v3 迁移和多模型 workspace 回归通过。
- 用户文件 `test/11.cemst` 不被修改、删除或提交。
- 所有未实机验证的 Minecraft 版本在文档中明确标记为“待验证”。

## 后续阶段

实机验证稳定后，再处理专家模式、动画参数、runtime 新指令、反向读取资源包和社区实体预设。普通用户流程不应依赖这些高级能力。
